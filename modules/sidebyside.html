The two, side by side

Everywhere else in this set the right answer had to be argued for. Here it is built in: two maps are mixed together on purpose, both methods are handed the mixtures, and what each one gives back can be compared against what actually went in. That makes it possible to ask the question the previous eight modules could not — not which method is better, but what has to be true of the data for each one to work.

The longer version

The two sources are the younger and older channel systems from the same synthetic survey the whole set uses, drawn as maps of where each one is. They are good sources for this because they are sparse — mostly empty, with a thin bright feature — which is exactly the kind of distribution module 07 showed is far from Gaussian.

Each mixture is a weighted sum of both, with the weights set by the angle. At zero the two mixtures are the two sources. Turning the angle up stirs them together, and at forty-five degrees each mixture is an equal blend.

The longer version

Both methods get the same two mixtures, standardized the same way. PCA returns the two directions of greatest spread; ICA whitens first and then turns until each projection is as far from Gaussian as it can be made.

The number under each map is how strongly it correlates with the source it comes closest to. One means the source came back exactly. The sign is meaningless, as module 04 established, so the magnitude is what is quoted.

3Now make PCA win

It can be done, and that is the point

Find a mixing angle where PCA recovers the sources as well as ICA does. One exists. Fill the bar.

Then try the strength slider, which looks like it ought to matter.

Why the curve has that shape

Module 03 found that with exactly two standardized attributes the first principal component always points at forty-five degrees, whatever the correlation between them. That result is doing all the work here. PCA's two directions are frozen at the diagonals before it sees anything, so the only question is whether the mixing happened to leave the sources sitting on those diagonals.

At forty and fifty degrees it did, and PCA returns the sources at 0.991 and 0.999. At zero degrees it did not, and PCA takes two sources that arrived already separated and hands back two blends of them at 0.739 each.

The spike down at exactly forty-five degrees is a different thing again, and it is the case module 04's Method tab said it was not covering. There the two mixtures are exactly uncorrelated and their two eigenvalues are both exactly 1.0000. When two eigenvalues are equal there is no widest direction — every direction is equally wide — so the answer is whatever the solver happened to produce, and it is not a property of the data at all.

Your angle marked in ink
The strength slider changes one mixture by up to a factor of sixty and moves neither method's answer at all. Both standardize their inputs first, and standardizing divides that factor straight back out. It is on the page because it looks like it should matter, and finding out that it does not is worth more than being told.

4Now make ICA lie

Switch the sources in the header

Switch to the Gaussian fields. ICA reports 0.98 against the true sources, so it looks like it worked.

It did not. Run it again from four different starting rotations and the answers disagree with each other.

The longer version

Module 07 established that a Gaussian is the one shape non-Gaussianity cannot distinguish, so with Gaussian sources there is nothing for the search to find and any rotation is as good as any other. Whitening a mixture of two independent Gaussians already returns a rotation of them, so a lucky rotation can score well against the truth by accident.

That is why measuring a method against a known answer is a weaker test than it looks. The test that catches this one is repeatability: change the starting rotation and see whether the answer changes. With the channel sources it does not. With Gaussian fields it does.

5What each one is for

Properties, not a recommendation

Nothing above says one method is better. It says they answer different questions and the data decides which question was the right one to ask.

On the seismic attribute set from modules 06 to 08, the best independent component separated the channel at 6.30 and the best principal component at 3.11, against a best-found 9.34. That is one target on one synthetic survey, and it is an argument for trying the method rather than a general result.

Why it matters

Where this shows up in real work

Real data never comes with the sources attached, so every judgment about whether a method worked has to be made without the comparison this module is built on.

  • A good-looking result is not evidence. Step 3 produces a near-perfect PCA recovery from a method with no mechanism for separating anything. Step 4 produces a near-perfect ICA recovery that is a coincidence. Both look like success.
  • Repeatability is a test you can run without truth. Re-run from a different start. If the components change, the data did not determine them. That works on a real survey, where measuring against the answer does not.
  • Check whether a control does anything. The strength slider here changes an input by a factor of sixty and moves nothing, because both methods standardize. Any parameter can be tested the same way in twenty seconds.
  • A result that improves when you add noise is telling you something. At 45 degrees here, noise takes PCA from 0.739 to 0.979, because it breaks a tie that had left the answer arbitrary. Nothing about the signal got better.
  • Know what your sources are likely to look like. ICA rests on the inputs being mixtures of a few non-Gaussian things. Sparse geological features qualify. Broad, smooth, diffuse ones do not, and on those ICA has nothing to work with.

Two points that are commonly confused. The first is that ICA supersedes PCA. ICA is normally run on PCA-whitened data — it is an extra rotation after PCA has done its work, not a replacement for it. The second is that a method matching a known answer proves it works. Step 4 is a worked counterexample, and it is the reason the verification file for this set tests repeatability rather than accuracy on the Gaussian case.

The honest summary of the whole set: PCA answers "which combinations vary most", reliably and in one step. ICA answers "which combinations look like single causes", by searching, sometimes failing, and never ranking its answers. Neither answers "which combination is the reservoir", and module 11 is about that.

Exercises

  1. Make PCA look like it works. Why: a good result from a method that cannot do the job is the most dangerous thing in this set, and producing one yourself is the way to stop trusting appearances. In step 3, hunt for the mixing angle that gives PCA its best recovery, then find its worst. Before starting: PCA has no mechanism for separating sources. Commit to how well you expect it to be able to do.
    HintAt 40 and 50 degrees PCA recovers the sources at 0.991 and 0.999 — visually indistinguishable from the ICA result. At 0, 5 and 85 degrees it manages about 0.74. ICA sits between 0.996 and 1.000 at every angle. The reason is module 03: with two standardized attributes the principal components always point at 45 and 135 degrees, so PCA's answer is fixed before it sees the data and the only question is whether the mixing put the sources there. The worst case is the one that should be easiest — at 0 degrees the mixtures are the sources, already separated, and PCA blends them back together. On a real survey you would see the good case and conclude the method separated your geology, with no way of knowing you had been lucky in the mixing.
  2. Find the control that does nothing. Why: a parameter that cannot matter is worth identifying, and the reason it cannot is module 03. In step 3, take the strength slider from 1× to 60× and watch both recovery numbers.
    HintNeither number moves, at any angle. Both methods Z-score their inputs before doing anything else, and standardizing divides out exactly the factor the slider applied. This is module 03's lesson arriving from the other direction: there the choice to standardize changed the answer completely, and here it is what makes a sixtyfold change in the data irrelevant. Both are the same fact. It is worth running this check on any parameter in any package — change it by a large factor, and if nothing moves, it is being removed somewhere upstream.
  3. Catch ICA succeeding by accident. Why: this is why the verification file for this set tests repeatability and not accuracy. Switch the sources to the Gaussian fields in the header, read ICA's recovery against the true sources, then look at the four starts in step 4.
    HintICA reports 0.981 and 0.978 against the true sources, which reads as a success. But four runs from different starting rotations agree with the first at 0.593, 0.565, 0.473 and 0.962 — they are not finding the same thing as each other, so none of them found anything. Whitening a mixture of two independent Gaussians already returns a rotation of them, so one rotation out of many scored well by luck. With the channel sources the same four runs agree at essentially 1.000. The difference between those two patterns is the test, and unlike the recovery number it can be run on data whose answer is unknown.
  4. Add noise and watch PCA get better. Why: it is the clearest possible demonstration that PCA’s result here is about geometry rather than about signal. In step 2, set the mixing angle to 45 degrees and take the noise from 0 to 60%. Before starting: commit to what noise will do to each method.
    HintPCA goes from 0.739 with no noise at all to 0.979 at 20% — adding noise nearly perfects it. ICA goes the other way, from 0.996 down to 0.976, and by 60% the two are level at about 0.855. The reason PCA improves is the degeneracy in step 3: at exactly 45 degrees the two eigenvalues are identical and PCA has no preferred direction, so its answer is arbitrary. Independent noise added to each mixture breaks that tie, gives PCA a direction to prefer, and the direction it then prefers happens to be a good one. Nothing about the signal improved. If a result gets better when you add noise, what you are looking at is a property of the arrangement and not of the data.
  5. Write down when you would use each. Why: the answer is a property of the data, and stating it in advance is how you avoid choosing by habit. In step 5, read the three comparison tables, then answer for your own data: are the attributes likely to be mixtures of a few sparse effects, or one broad continuum?
    HintIf the attributes are redundant and you want them compressed, decorrelated, or reduced to three channels for a blend, PCA does that exactly, in one step, reproducibly, with a ranking. If you believe a few distinct physical effects are superimposed in your attributes and you want them pulled apart, ICA is the method built for that — provided those effects are sparse or otherwise non-Gaussian, which sparse geological features usually are and broad smooth trends usually are not. The two are not alternatives in practice: ICA is normally run on PCA-whitened data, so the real question is whether to stop after PCA or keep going.

If you remember nothing else

  • PCA can appear to unmix sources. At one mixing angle here it recovers both at 0.991 and at another 0.739 — and the worst case is zero mixing, where the sources arrive already separated and it blends them back together.
  • That is module 03 arriving with teeth. With two standardized attributes the components always point at 45 degrees, so PCA’s answer is fixed before it sees the data.
  • ICA can appear to succeed on data it cannot handle. With Gaussian sources it scores 0.98 against the truth and four different starts disagree with each other.
  • Repeatability is the test you can actually run. Re-run from a different start. It works without knowing the answer, which is the situation you are always in.
  • A control that changes an input sixtyfold and moves nothing is being standardized away upstream. Test any parameter this way.
  • ICA is an extra rotation after PCA, not a replacement for it. The whitening step is PCA.
  • The choice is a statement about your data. Mixtures of a few sparse effects suit ICA. Redundancy you want compressed suits PCA.

Method

What is computed, and what is left out

The sources are maps of where each channel system sits in the same synthetic survey the rest of the set uses: for each trace, a value that peaks on the channel axis and falls to zero at its margin, and zero everywhere else. Both are standardized. They are sparse and strongly non-Gaussian, with excess kurtosis of 6.25 and 11.15, which is what makes them suitable sources. They are not quite independent of each other — the two channels cross, so the maps correlate at −0.091 — and a perfectly independent pair is not available from real geology.

The mixing is a rotation by the chosen angle followed by a scaling of the first mixture by the strength slider, which runs from 1× to 60× in half-decade steps. Noise, when added, is Gaussian and independent on each mixture. At a mixing angle of zero the two mixtures are the two sources.

Both methods are run standardized, which is the correlation route of module 03 and the arrangement ICA implementations use anyway. That is why the strength slider has no effect: standardizing divides it straight back out. It was left on the page deliberately.

Recovery is the largest absolute correlation between a returned component and a true source, taking the best match for each source. Absolute, because the sign of a component is arbitrary. Taking the best match, because the order is arbitrary too. Both of those conventions hide a real difficulty that modules 04 and 08 cover: on real data there is no true source to match against and the matching is done by eye.

The degenerate case at forty-five degrees. There the two mixtures are exactly uncorrelated and both eigenvalues are 1.0000, so the principal directions are genuinely undetermined and what the solver returns is an artifact of the solver. Module 04's Method tab lists repeated eigenvalues as something that does not arise on real attribute data and is the reason textbook uniqueness statements carry a condition. It arises here, on constructed data, and it is left in rather than designed around because it is the honest thing for the curve to do.

Simplifications, stated plainly. Two sources and two mixtures is the smallest case that shows anything, and a real problem has more of both. The mixing is linear and the same everywhere in the survey, which is the assumption ICA rests on and which real data does not always satisfy. The sources are known exactly, which never happens. Every number on this page is one synthetic survey and should be read as an illustration of a mechanism rather than as a measured property of seismic data in general.

Where this departs from production software. Nowhere in the arithmetic. The comparison itself is not something a package offers, because it needs the sources, and assembling it is the reason this module exists.
